# Half-GCD による Berlekamp–Massey の実測

2026-09-08 に実装・計測。
今回の実装では、ランダム列はおよそ 8,000 項から通常 BM より速くなり、
65,536 項では **1,331 ms → 204 ms、6.52 倍**だった。
一方、長い列でも復元する次数が小さい場合は通常 BM の方が速い。
このため `berlekamp_massey_fast` を別 API として追加した。

## 計測条件と再現

- Apple M3 Pro、メモリ 18 GiB、macOS arm64。
- GCC 15.2.0、`-std=c++20 -O2 -DNDEBUG`、`modint998244353`。
- 比較対象は現行の `berlekamp_massey<FieldAddSubMulDiv<mint>>`。
  内積の剰余回数削減などが入った版であり、素朴な未最適化 BM ではない。
- ケースごとに固定した同一入力を 1 回ウォームアップして、5 回測定した中央値。
  通常版と高速版の先行順を毎回交代。実行は単一スレッド。
- 入力生成、入出力、検算、checksum 計算は計測外。
  関数内の配列確保・コピー・NTT などは計測内。
- 各サイズ・ケースの入力は 1 seed。5 seed の平均ではない。
  専用機で CPU を固定した測定ではないので、特に数 % の差は目安。

```sh
g++-15 -std=c++20 -O2 -DNDEBUG -I. benchmark/half_gcd.cpp -o /tmp/half-gcd-bench
/tmp/half-gcd-bench 5 65536 262144
```

[計測コード](half_gcd.cpp)、[全 170 回の生データ](half_gcd_results.csv)、
[中央値・最小値・最大値](half_gcd_summary.csv)。CSV の `-1` は未計測。
比較対象 BM の SHA-256 は
`79ffdbbfd0653d92246a55ed8a33363fb007d79a949537c24bb8d59d61cec3de`。

以下の $n$ は **入力列の項数**。行列の次元や漸化式の次数ではない。
速度比は「通常 BM の時間 / Half-GCD の時間」で、大きいほど高速化している。

通常 BM は大きいサイズで倍増ごとにおよそ 4 倍、Half-GCD は約 2.1–2.2 倍。
理論上の $O(n^2)$ と $O(n\log^2 n)$ に対応する傾向が見える。
NTT の長さが 2 の冪に切り上がるため、実時間は $n$ の滑らかな関数にはならない。
交差点付近の差は小さく、8,192 項の 5 回の範囲は通常版 21.532–24.416 ms、
Half-GCD 19.604–24.380 ms と重なる。8,000 項という値は厳密な閾値ではない。

## 低次数の列と特殊な列

`recurrence` は、次数 $d$ のランダムな分母 $Q$ と次数 $d-1$ 以下の分子 $P$ から
$P/Q\bmod x^n$ を生成。生成は計測外で、実際に復元した次数が下表の $d$。

| n | d | 通常 BM (ms) | Half-GCD (ms) |
| ---: | ---: | ---: | ---: |
| 4,096 | 1 | 0.015 | 0.088 |
| 4,096 | 8 | 0.024 | 0.238 |
| 4,096 | 32 | 0.067 | 0.699 |
| 4,096 | 128 | 0.240 | 2.255 |
| 4,096 | 512 | 1.066 | 3.182 |
| 65,536 | 1 | 0.230 | 1.351 |
| 65,536 | 8 | 0.351 | 3.711 |
| 65,536 | 32 | 1.014 | 10.742 |
| 65,536 | 128 | 3.341 | 39.189 |
| 65,536 | 512 | 14.494 | 40.116 |

通常 BM のより細かい計算量は $O(n(d+1))$。
$d\ll n$ なら通常版の定数倍が小さく、今回の $d=32,128$ では約 11 倍速い。
Half-GCD も低次数では処理が早く終わることがあるが、一般的な行列演算・除算の定数倍が残る。

| 特殊ケース (n=65,536) | d | 通常 BM (ms) | Half-GCD (ms) |
| --- | ---: | ---: | ---: |
| 全零 | 0 | 0.195 | 0.042 |
| 最後の項だけ 1 | 65,536 | 0.212 | 0.466 |
| 最初の項だけ 1 | 1 | 0.241 | 1.087 |

全零列は高速版の明示的な早期リターンが効く。
最後の項だけ 1 の場合、通常版も次数が増えるのは最後だけなので軽い。
「最終次数が大きければ必ず高速版が勝つ」という判断もできない。

## 手法の説明

Euclid の 1 ステップを多項式行列で書くと、

$$
\binom{b}{a-qb}=\begin{pmatrix}0&1\\1&-q\end{pmatrix}\binom{a}{b},
\qquad q=a\mathbin{\mathrm{div}}b
$$

となる。Half-GCD は、高次側の係数で再帰してこの変換行列をまとめて求め、
剰余の次数が約半分になるまで一気に進める。
行列の積・適用を NTT による多項式乗算で行い、
$T(n)=2T(n/2)+O(M(n))=O(M(n)\log n)$、
$M(n)=O(n\log n)$ なら $O(n\log^2 n)$ になる。
再帰の基本形は [Li–Moreno Maza–Schost (2007), Appendix A3](https://cs.uwaterloo.ca/~eschost/publications/fp097-li.pdf) を参考にした。

BM への帰着では、数列を逆順に並べた多項式
$T(x)=a_{n-1}+a_{n-2}x+\cdots+a_0x^{n-1}$ を作る。
特性多項式 $U(x)=x^d-c_1x^{d-1}-\cdots-c_d$ が漸化式を表す条件は

$$ \deg(U(x)T(x)\bmod x^n)<\deg U(x) $$

である。$(x^n,T)$ に拡張 Euclid を適用し、各剰余を $r=vx^n+uT$ と表して、
初めて $\deg r<\deg u$ となった時点の $u$ を monic にする。
これが最短漸化式となる。Half-GCD で中間点まで進め、その後に必要なら通常の除算を 1 回足せばよい。
[AtCoder の解説 §6](https://info.atcoder.jp/entry/algorithm_lectures/linearly_recurrent_sequence_reconstruction) に帰着と最小性の証明がある。

単に $\gcd(x^n,T)$ を出力すればよいわけではない。
**途中の Bézout 係数と停止条件が必要**であり、今回の実装では変換行列を保持している。

## 他の用途とコード共通化

| 用途 | Half-GCD との関係 | 今回の実装との共通化 |
| --- | --- | --- |
| 多項式 GCD | Euclid を最後まで進める | 実装済み。共通の `half` を `full` から使う |
| 多項式拡張 GCD | 最後の剰余を表す Bézout 係数も返す | 実装済み。同じ変換行列から取り出す |
| 一般の多項式を法とする逆元 | `s*f+t*g=1` の `s` を取り出す | 実装済み。拡張 GCD に薄いラッパーを加える |
| 有理関数復元・Padé 近似 | `Q*S == P (mod x^n)` を次数制約つきで解く。BM はその一種 | 行列・除算・再帰は再利用可能。一般の次数境界への停止処理と正規化は追加が必要 |
| 終結式 (resultant) | Euclid の剰余列から次数と最高次係数の寄与を積み上げる | Half-GCD 方式に拡張できるが、今回の行列だけでは不足。寄与を追跡する追加状態が必要 |

GCD・拡張 GCD に Half-GCD を使うことは [NTL の公式ドキュメント](https://libntl.org/doc/lzz_pX.cpp.html) にも明記されている。
BM と逆元の共通実装の具体例は [CP-Algorithms の `euclid.hpp`](https://lib.cp-algorithms.com/cp-algo/math/poly/impl/euclid.hpp.html)。
Half-GCD 方式の終結式の実装例は [FLINT 開発者による追加報告](https://groups.google.com/g/flint-devel/c/7fV_Ka9GWu0) にある。
上表の共通化範囲は、これらの資料と今回の実装を踏まえた設計上の判断。
一般 Padé と終結式の API は今回追加していない。

ユーザーが挙げた [Inv of Polynomials](https://judge.yosupo.jp/problem/inv_of_polynomials) は、まさに共通化できる用途。
法 $g$ が非定数の場合は、$\gcd(f,g)=1$ のときに限り逆元が存在する。
`f(0)!=0` は必要ない。例えば $x^{-1}\bmod(x^2+1)=-x$。
公式問題は非零定数の法も許し、この場合は零多項式を返す仕様。
[確認した公式問題文の版](https://github.com/yosupo06/library-checker-problems/blob/04c8de378bab67be926325de2871f0babb8e6451/polynomial/inv_of_polynomials/task.md)。

同じ共通実装での逆元単体の実測は次の通り。
$\deg f=n-1$、$\deg g=n$ の密なランダム多項式。通常の拡張 Euclid との速度比較はしていない。

| n | 多項式逆元 (ms) |
| ---: | ---: |
| 1,024 | 3.235 |
| 4,096 | 16.699 |
| 16,384 | 86.133 |
| 65,536 | 403.628 |

既存の FPS の `inv(n)` は法が $x^n$ に限られ、Newton 法で $O(M(n))$。
この特殊な逆数には引き続き既存実装を使う。
Half-GCD の高速除算も内部では FPS の逆数を利用しており、
「共通の FPS・NTT → 高速除算 → Half-GCD → BM / 拡張 GCD / 一般逆元」という依存関係になる。

## 実装内容と定数倍

- [half_gcd.hpp](../math/fps/half_gcd.hpp)：除算、多項式 $2\times2$ 行列、Half-GCD、
  `polynomial_gcd`、`polynomial_extgcd`、`polynomial_inv_mod`。
- [berlekamp_massey_fast.hpp](../math/fps/berlekamp_massey_fast.hpp)：BM への帰着。
  33 行の呼び出し口で、除算・行列・再帰は共通実装に置いている。
- [API ドキュメント](../docs/math/fps/berlekamp_massey_fast.md)。

多項式行列同士の積で、各成分の畳み込みを独立に 8 回実行すると
最大 24 回の NTT / 逆 NTT が必要になる。
変換後の値で行列積を計算すれば、入力 8 回・出力 4 回の計 12 回にできる。
行列・ベクトル積も同様に計 12 回から 8 回に削減した。
また、商が短い除算では通常の筆算を使い、小さい Half-GCD は通常の互除法に切り替える。
切り替え値 16 / 32 / 64 / 128 / 256 を予備計測し、密な列で良好だった 128 を採用した。
この値は通常 BM と高速 BM を切り替える閾値ではない。

さらに定数倍を詰めるなら、積の必要な係数範囲だけを計算する middle product、
作業バッファの再利用、GCD / 逆元で不要な行列成分の計算削減などが候補。
今回の数値は最速の Half-GCD 一般を代表するものではなく、このライブラリ上の実装の比較。

## 採用時の判断

既知の全項を一括処理し、長くて次数も大きい列なら高速版を選ぶ価値がある。
今回なら 16,000 項で約 2 倍、65,536 項で約 6.5 倍。
短い列・低次数・逐次更新や早期終了が必要な用途では通常版が適している。

BBLA では BM 以外の射影列生成・内積・行列作用の時間が残る。
この BM 単体の速度比が BBLA 全体の速度比になるわけではない。
前回の [BBLA の段階別計測](bbla.md) の `n` は行列次元で、BM の入力長はその 2 倍なので、
このレポートの `n` とは区別する。
