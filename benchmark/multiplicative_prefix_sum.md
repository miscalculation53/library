## 測定対象

2026-09-07 に、手元の macOS / x86_64 環境で計測。
コンパイラは Homebrew GCC 15.2.0、`-std=c++17 -O2 -Wall -Wextra`。
`NDEBUG` は定義していない。同時に別のベンチマークを動かさず、各実行を別プロセスとした。
実時間はプロセスの起動・終了を含み、最大 RSS は `wait4` で取得した。
これは手元の測定であり、オンラインジャッジの判定ではない。

対象は [Sum of Multiplicative Function (Large)](https://judge.yosupo.jp/problem/sum_of_multiplicative_function_large)。
[公式設定](https://raw.githubusercontent.com/yosupo06/library-checker-problems/master/number_theory/sum_of_multiplicative_function_large/info.toml)
では制限 30 秒、$N\le10^{13}$、法 $469762049$。
関数は $f(p^e)=ae+bp$。以下は $a=123456789,b=234567890$ とした。

素数の個数、素数の和、乗法的関数の和の **三段階すべて**を含む。
各方式は同じ `FieldAddSubMulDiv<static_modint32<469762049>>` で比較した。

## 3/4 乗版と 2/3 乗版

どちらも除算不要。表の時間はプロセス全体の実時間。
$N=10^{13}$ は各 3 回の中央値、それ以外は各 1 回。

| $N$ | `_sieve`：$O(N^{3/4}/\log N)$ | `_sieve_2_3`：$O(N^{2/3})$ | 速度比 |
| --- | ---: | ---: | ---: |
| $10^9$ | 0.094 秒 | 0.095 秒 | ほぼ同じ |
| $10^{10}$ | 0.233 秒 | 0.180 秒 | 1.30 倍 |
| $10^{11}$ | 1.013 秒 | 0.574 秒 | 1.77 倍 |
| $10^{12}$ | 4.882 秒 | 2.283 秒 | 2.14 倍 |
| $10^{13}$ | 24.645 秒 | 10.324 秒 | 2.39 倍 |

最大ケースの 3 回の実時間は、3/4 乗版が 24.522 / 24.645 / 25.172 秒、
2/3 乗版が 10.293 / 10.324 / 10.906 秒。
最大 RSS の最大値は、それぞれ約 237 MiB、273 MiB。
小さい入力の値には起動と計測のオーバーヘッドが含まれるため、細かい差の比較には向かない。

一回の測定の内訳：

| 段階（$N=10^{13}$） | 3/4 乗版 | 2/3 乗版 |
| --- | ---: | ---: |
| 素数の個数 | 6.895 秒 | 2.806 秒 |
| 素数の和 | 6.947 秒 | 2.769 秒 |
| 素数上の和から乗法的関数の和を復元 | 10.721 秒 | 4.624 秒 |

復元部分だけで約 2.32 倍、素数上の和の準備も含めて約 2.39 倍となった。
全ての測定で方式間の出力は一致した。最大ケースの出力は `284866429`。

## 疎な log/exp 版との比較（削除済みの実装）

こちらは小整数の逆元を使う $O(N^{2/3}/\log N)$ 版。
$N=10^{13}$、同じ $a,b$ で測定した。
この実装と専用の疎な保存形式は 2026-09-10 に削除した。以下は削除前の測定記録。

| 前計算境界 $K$ | 実時間 | 最大 RSS |
| --- | ---: | ---: |
| $\lfloor N^{2/3}\rfloor$ | 26.38 秒 | 2396 MiB |
| $\lfloor N^{2/3}\rfloor/8$ | 18.79 秒 | 649 MiB |

前者は当時 log/exp 版を使っていた通常版 verify、後者は当時のベンチマーク実行ファイルでの各一回の値。
前計算境界を下げることで疎な係数を集約するコストとメモリを減らせた。
今回の入力範囲と実装では、除算不要の 2/3 乗版のほうが速かった。
漸近的に $\log N$ で割れることだけでは、実際の優劣は決まらない。

## 複数テストケース

各ケースを同じ $N,a,b$ として、$T\sqrt N=10^6$ を満たす二つの入力を測定した。
全方式の出力列は一致した。いずれも各一回の実時間。

| 入力 | 3/4 乗版 | 2/3 乗版 | log/exp 版（$K\approx N^{2/3}/8$、平方根以上） |
| --- | ---: | ---: | ---: |
| $T=100,N=10^8$ | 0.980 秒 | 0.819 秒 | 2.573 秒 |
| $T=10000,N=10^4$ | 0.360 秒 | 0.401 秒 | 3.987 秒 |

小さい $N$ では、2/3 乗版の準備が増える分、3/4 乗版のほうが速い場合もある。
そのため通常の入口では、入力の大きさに応じて両者を使い分ける。

## 自動選択の境界

`prime_prefix_sum(a)` と `multiplicative_prefix_sum(P, get)` は、
$N<10^6$ で基本版、それ以上で Fenwick Tree 版を呼ぶ。
どちらも除算不要で入力の `k()` を維持する。
log/exp 版は削除済みで、自動選択には含まれない。

境界の検討には次の追加計測を使った。
基本版も商集合上で DP を行い、密な範囲の残りは直接篩う現在の実装を使用。
起動の影響を避け、**素数の個数・素数の和・乗法的関数の復元の関数内時間の合計**を比較した。
同じ入力で各 2 回の平均。$a,b$ とコンパイル条件は上と同じ。

| $N$ | ケース数 | 基本版の計算時間 | Fenwick Tree 版の計算時間 |
| --- | ---: | ---: | ---: |
| $10^4$ | 10000 | 0.258 秒 | 0.280 秒 |
| $10^5$ | 3162 | 0.312 秒 | 0.304 秒 |
| $10^6$ | 1000 | 0.416 秒 | 0.386 秒 |
| $10^7$ | 316 | 0.626 秒 | 0.531 秒 |
| $10^8$ | 100 | 0.894 秒 | 0.735 秒 |
| $10^9$ | 31 | 1.319 秒 | 0.964 秒 |

$N=10^5$ は差が小さく、素数上の和だけでは基本版が僅かに速かった。
両段階で一貫して Fenwick Tree 版が有利になった $10^6$ を共通の境界とした。
これは環や実行環境ごとの最速を保証する境界ではない。
比較用コードは `internal` の `_sieve` / `_sieve_2_3` を呼ぶ。通常の利用では公開された自動選択の二関数を使う。

自動入口を加えた実行ファイルでも確認した。以下は各一回で、方式間の出力は一致した。

| 入力 | 呼び方 | 実時間 | CPU 時間 | 最大 RSS |
| --- | --- | ---: | ---: | ---: |
| $T=1,N=10^{13}$ | 自動 | 12.361 秒 | 11.736 秒 | 273.4 MiB |
| $T=1,N=10^{13}$ | 2/3 乗版を直接指定 | 11.849 秒 | 11.775 秒 | 273.4 MiB |
| $T=10000,N=10^4$ | 自動 | 0.401 秒 | 0.383 秒 | 6.2 MiB |
| $T=10000,N=10^4$ | 基本版を直接指定 | 0.388 秒 | 0.377 秒 | 6.2 MiB |
| $T=10000,N=10^4$ | 2/3 乗版を直接指定 | 0.424 秒 | 0.406 秒 | 6.2 MiB |

最大ケースの答えは `284866429`。自動版でも手元では 30 秒以内だった。
大きい入力の CPU 時間は直接指定とほぼ同じで、自動選択による目立つ負担は見られなかった。
切り替え境界の前後、$K>\sqrt N$、整数環・零因子のある環などの正当性も C++17・20 で検証した。

## 再現方法

一般化された Euler 積による構築との比較は
[別の測定記録](euler_product_prefix_sum.md) にまとめた。当時の一般 Euler 積を使う入口は削除済みで、この比較の記録だけを残している。

リポジトリのルートでコンパイルする。

```sh
g++-15 -std=c++17 -O2 -Wall -Wextra -I. benchmark/multiplicative_prefix_sum.cpp -o /tmp/mpbench
python3 benchmark/multiplicative_prefix_sum.py /tmp/mpbench --n 10000000000000 --repeat 3
```

Python 側は各方式の答えを比較し、JSON Lines で実時間・CPU 時間・最大 RSS・段階別の時間を出力する。
`--methods auto sieve sieve23` が既定値。`--cases`, `--a`, `--b`, `--timeout` も指定できる。
選べる方式は `auto`, `sieve`, `sieve23`。macOS / Linux 用で、追加パッケージは不要。
`--cases` を増やす場合は、問題の $T\sqrt N\le10^6$ の制約にも注意する。

Large 版用の verify は
[`sum_of_multiplicative_function_large.test.cpp`](../verify/yosupo/sum_of_multiplicative_function_large.test.cpp)。
逆元を使わない `RingAddSubMul<mint>` を指定している。
自動入口を設ける前のこの verify（2/3 乗版を直接指定）も最大ケースで実行し、11.457 秒・最大 RSS 257.9 MiB、
出力 `284866429` を確認した（初回実行一回の値）。
小さい 66 ケースは試し割りによる独立した計算とも一致し、C++17・20 の両方で確認した。
