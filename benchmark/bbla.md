# Black Box Linear Algebra の高速化

2026-09-08 に計測。変更前は `8943a007` の BM・BBLA・`Matrix::det_sparse`。
`bbla.cpp` に変更前の実装を保存してあるので、新旧を同じバイナリで比較できる。

## 再現方法

リポジトリのルートで実行する。

```sh
g++-15 -std=c++20 -O2 -Wall -Wextra -I. benchmark/bbla.cpp -o /tmp/bbla-bench
/tmp/bbla-bench 2000 5
/tmp/bbla-bench 4000 5
```

macOS、GCC 15.2.0、`modint998244353`、`-O2`。
1 回ウォームアップ後の 5 回の中央値。新旧を交互に先に実行し、各実行で乱数 seed を揃える。
入力の生成は計測外、`Matrix::det_sparse` の密行列から CSR への変換は計測内。
すべての行で新旧の返り値の checksum が一致することも確認する。
行列を作用させるコードと構造によって改善率は変わる。

- `BM_random`：長さ `2n` のランダムな数列。BM 単体は約 1.9–2.0 倍。
- `bidiagonal`：非零の対角と上隣接成分を持つ行列を、その場で作用させる。
  作用の計算が支配的なので、全体の改善は約 6–9% にとどまる。
- `identity`：単位行列。`minpoly` は最後まで観測し、`solve` は検算付きで早期終了する。
- `32_eigenvalues`：対角が 32 種類の値を繰り返す正則行列。
  このように右辺の最小多項式の次数が小さい場合、`solve` は大幅に速くなる。
  単位行列の大きな速度比を一般の行列にも期待することはできない。
- `sparse_4n`：各行 4 個のランダムな要素を持つ CSR の作用。
  同じ作業バッファを再利用する作用を新旧に渡す。重複位置は加算扱い。
  最小多項式・行列式は約 1.2–1.3 倍。
- `Matrix_det_sparse`：既存の `Matrix` API で二重対角行列の行列式を計算。約 1.46 倍。

## 変更内容

1. 32 bit modint の内積を 64 bit でまとめて積和し、剰余の回数を削減。
   `mod <= 2^30` は 16 項、それ以上の正の `int` の法では 4 項ずつ処理する。
2. BM の係数更新では、符号反転をループ外に移す。
   次数が増える場合だけ係数を退避し、逆数を更新する。逐次更新用 API も追加。
3. 最小多項式で生成する列を `2n+1` 項から必要な `2n` 項にし、
   最後の不要な作用も省略。作用回数は `2n+1` 回から `2n-1` 回になる。
4. `solve` は右辺から Krylov 列を作る。低次数なら途中で候補を作り、
   `Ax == b` を検算して終了する。失敗時は継続または再試行する。
5. `Matrix::det_sparse` の作用は出力バッファを再利用し、
   `majority == 0` のとき不要なベクトル全体の和を省略する。

## 検証

- `verify/mytest/ai/bbla.test.cpp`：零行列・単位行列・重複固有値・nilpotent・Jordan・乱数行列など
  495 行列を、掃き出し法の行列式・直接の行列ベクトル積と照合。
- GF(2) の長さ 0–10 の全 2,047 数列について、全係数の列挙による独立の最小次数 oracle と BM を照合。
- 32 bit の法の境界、64 bit modint、Montgomery modint、独自の体、逆向き iterator の内積を確認。
- 零の射影を強制して `solve` の再試行を確認。
  長い零の観測列からの不正な早期終了が起きないことも確認。
- `FPS::pow_mod` と組み合わせた `A^k v`、BMBM と組み合わせた `u^T A^k v` を、
  `k=10^18` を含めて通常の行列累乗と照合。
- 保存済み Library Checker データ：既存の疎行列式 24、線形漸化式復元 18、
  漸化式の第 k 項 20、行列式 25、新規の BBLA 直接呼び出し 24 の計 111 ケース。
  漸化式復元は係数が一意でない場合があるので、最小次数と漸化式の成立を検査。
- C++17 / C++20 で新規の回帰テストを実行。
  BBLA・BM・内積の独立したテストには Apple Clang の ASan / UBSan も適用。

## Half-GCD を導入した場合の効果の上限

同日の追加計測。最小多項式の計算を、射影列の生成と BM に分けた。
ここで `n` は行列の次元で、BM に渡す列の長さは `2n`。
**Half-GCD の実装比較ではなく、BM の高速化が全体に及ぼす効果の上限を調べる計測**。

```sh
g++-15 -std=c++20 -O2 -I. benchmark/bbla_profile.cpp -o /tmp/bbla-profile
/tmp/bbla-profile
```

前と同じ環境で、ウォームアップ 1 回の後の 5 回の中央値。
割合・上限は各段階の中央値の和から算出する。入力生成は計測外。
`cyclic_shift` の作用は `std::rotate` による循環シフト。

| ケース | n | 射影列生成 (ms) | BM (ms) | BM の割合 | BM を 0 ms にできた場合の速度比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `bidiagonal` | 4000 | 202.069 | 19.622 | 8.9% | 1.10x |
| `sparse_4n` | 4000 | 118.940 | 19.072 | 13.8% | 1.16x |
| `cyclic_shift` | 4000 | 45.282 | 19.618 | 30.2% | 1.43x |
| `bidiagonal` | 8000 | 810.072 | 78.418 | 8.8% | 1.10x |
| `sparse_4n` | 8000 | 469.413 | 75.553 | 13.9% | 1.16x |
| `cyclic_shift` | 8000 | 177.824 | 77.906 | 30.5% | 1.44x |

Half-GCD による復元は $O(M(N)\log N)$、FFT/NTT の乗算なら $O(N\log^2 N)$。
しかし、通常の BBLA では $2n$ 回程度の行列作用に加え、
長さ $n$ の内積を $2n$ 回程度求めるので、その部分に $O(nt+n^2)$ が残る。

今回のランダム疎行列では BM の時間を仮に 1/10 にしても、全体の速度比は約 1.14 倍。
循環シフトのように作用が軽いケースでは BM の比重が大きく、改善余地も大きい。
実際の Half-GCD は 0 ms ではなく、NTT・多項式行列の積・再帰などの定数倍もあるので、
採用する閾値は実装後の比較で決める必要がある。

BM 単体で長い数列を入力する用途には、Half-GCD 版の追加を検討する価値がある。
一方、低次数の数列に対する通常の BM は $O(Nd)$（$d$ は復元する次数）で済み、
`solve` では逐次更新から検算付き早期終了にも使えるため、この用途を維持したい。

理論と帰着は [AtCoder の解説 §6.6](https://info.atcoder.jp/entry/algorithm_lectures/linearly_recurrent_sequence_reconstruction)、
Half-GCD の実装面は [Li, Moreno Maza, Schost (2007)](https://cs.uwaterloo.ca/~eschost/publications/fp097-li.pdf) を参照。
