このドキュメントには AI による作成・変更が含まれています。

## 概要

最大流・最小カットを求める。ACL の最大流と同じ `add_edge`・`flow`・`get_edge`・`edges`・`change_edge`・`min_cut` を備える。自己ループ・多重辺を扱える。

残余グラフは [CSR](../ds/csr.md) で連続配置し、逆辺を配列全体の添字で参照する。追加した辺は一時配列へ蓄え、最初の探索前に構築する。`build()` で先に構築することもできる。探索後に辺を追加した場合も、次の構築時に現在の流量を引き継ぐ。

利用者の辺番号と探索用の辺を分け、構築時に自己ループ・容量 $0$ の辺を探索用グラフから除く。最大 $64$ 箇所から計最大 $1024$ 本をサンプルし、同方向の多重辺が十分見つかった場合は、全体を $O(n+m)$ で集約する。自己ループ・容量 $0$ がサンプルの過半数なら、除外だけを行う軽い構築を選ぶ。合計容量が `Cap` の範囲を超える場合は複数の辺に分ける。サンプルの結果は速度だけに影響する。

集約した辺の流量変化は、探索の終了時に元の各辺へ配分する。`get_edge`・`edges` は追加した全辺の容量・流量を返し、自己ループに `change_edge` で設定した流量も保つ。集約辺の構成要素と除外した辺だけに元の辺の記録を持たせ、単独の辺は残余グラフを直接参照する。使用メモリは $O(n+m)$。

`flow` は Dinic で開始し、探索量が増えると highest-label Push–Relabel も試す。流量の進捗と頂点の通過容量を見て Dinic の試行量を延長する。Push–Relabel が長引いた場合は、それぞれの残余グラフを保持して両方式を交互に進める。試行量を倍増させることで、Dinic の計算量保証を保つ。`dinic`・`push_relabel` で方式を指定することもできる。

自動選択の状態保存には追加で $O(n+m)$ のメモリを使う。

Push–Relabel は gap heuristic と global relabeling を使う。流量上限分を仮想始点から供給し、余った分を返す。内部の余剰流の総和も上限以下に保つため、始点から出る容量の総和が `Cap` の範囲を超える入力も扱える。Dinic は最短増加路長 $64$ 以下で再帰を使い、それより深い探索を明示的なスタックで処理する。

## 使用例

```cpp
#include "flow/maxflow.hpp"

MaxFlow<ll> g(4);
int id = g.add_edge(0, 1, 3);
g.add_edge(0, 2, 2);
g.add_edge(1, 2, 1);
g.add_edge(1, 3, 2);
g.add_edge(2, 3, 3);

ll first = g.flow(0, 3, 2);  // 2
ll rest = g.flow(0, 3);      // 3。追加で流した量を返す
auto e = g.get_edge(id);    // from, to, cap, flow
auto cut = g.min_cut(0);    // {true, false, false, false}

// 容量を増やし、現在のフローから継続する。
g.change_edge(id, e.cap + 2, e.flow);
ll extra = g.push_relabel(0, 3);
```

## 詳細なドキュメント

### MaxFlow

```cpp
template <class Cap>
struct MaxFlow;
```

`Cap` は `bool` 以外の整数型。`int`・`ll`・符号なし整数・`i128`・`u128` を使用できる。以下、頂点数を $n$、追加した辺数を $m$、構築後の探索用の辺数を $q\leq m$ とする。$q$ は逆辺を含めずに数える。

#### コンストラクタ

```cpp
MaxFlow();
explicit MaxFlow(int n);
```

頂点 $0,\ldots,n-1$、辺数 $0$ のグラフを作る。引数を省略すると $n=0$ とする。

##### 制約

- $0 \leq n$

##### 計算量

- $O(1)$

#### size / num_of_edges

```cpp
template <class I = ll> I size() const;
template <class I = ll> I num_of_edges() const;
```

頂点数・追加した辺数を返す。

##### 計算量

- $O(1)$

#### add_edge

```cpp
int add_edge(int from, int to, Cap cap);
```

`from` から `to` へ容量 `cap`、流量 $0$ の有向辺を追加し、追加順の辺番号を返す。`flow` の実行後も辺を追加して継続できる。

##### 制約

- $0 \leq \mathrm{from},\mathrm{to}<n$
- $0 \leq \mathrm{cap}$

##### 計算量

- ならし $O(1)$

#### build

```cpp
void build() const;
```

現在の辺を簡約し、残余容量を CSR に配置する。元の辺番号・容量・流量を保つ。`flow`・`dinic`・`push_relabel`・`min_cut` は必要に応じて自動で呼ぶため、明示的な呼出しは任意。

##### 計算量

- 初回と再構築が必要な変更後は $O(n+m)$。それ以外は $O(1)$

#### flow / dinic / push_relabel

```cpp
Cap flow(int s, int t, Cap flow_limit = numeric_limits<Cap>::max());
Cap dinic(int s, int t, Cap flow_limit = numeric_limits<Cap>::max());
Cap push_relabel(int s, int t, Cap flow_limit = numeric_limits<Cap>::max());
```

現在の残余グラフで、`s` から `t` へ `flow_limit` まで流せる限り流し、今回追加で流した量を返す。上限を省略すると最大流を求める。上限が $0$ の場合は $0$ を返す。初回と再構築が必要な変更後は、探索前に `build()` を行う。

同じ `s, t` に対して繰り返すと、現在のフローから継続する。方式を変えて継続することもできる。異なる端点を指定すると、その時点の残余グラフで指定された方向へ流す。例えば `t` から `s` への実行で、以前のフローを取り消せる。

`flow` の選択手順は次の通り。

1. 始点から出る残余容量と終点へ入る残余容量の合計を使い、流量上限を絞る。合計は指定上限で打ち切って計算する。
2. $n<128$ または $q<512$ の場合は Dinic を使う。
3. それ以外は $B=n+2q$ とし、配列初期化と辺の探索の回数を数えながら Dinic を進める。最短路長が $16$ 以下なら $8B$、それより長ければ $2B$ を目安にする。
4. 最初に予算へ達したとき、流量上限の半分以上を流せている場合、または各内部頂点の通過容量が小さい場合は $B$ を $8$ 倍して Dinic を続ける。通過容量は残余容量の出入りの合計の小さい方とし、容量の最大公約数を単位として $8$ 以下かを調べる。自己ループを除き、必要なら増加路に含まれる可能性がある頂点だけで再判定する。このとき、行き止まりを除いた端点のカットでも残りの流量を評価する。また、容量 $8$ 単位以下の辺を外した到達集合からカットを作り、残りの流量が $32$ 単位以下と分かる場合は、流量依存の保証を踏まえて $B$ を $64$ 倍する。
5. Dinic の試行が予算に達したら残余容量を保存し、予算 $8B$ で Push–Relabel を試す。Push–Relabel も予算に達した場合は Dinic 用の残余グラフを作り、$B$ を倍増して Dinic を再開する。以後は両方式の状態を保持して交互に進め、先に完了した方式の結果を採用する。

Dinic の打切り時は探索を戻してフロー保存則を満たし、既に流した分を引き継ぐ。Push–Relabel の予算には初期化・辺走査・gap による頂点走査も含める。予算は処理量の目安であり、入力によって各方式の速さは変わる。両方式とも、始点・終点の残余容量による上限の絞り込みを行う。

##### 制約

- $0 \leq s,t<n$、$s\ne t$
- $0 \leq \mathrm{flow\\_limit}$
- 上限を省略して最大流を求める場合、今回追加で流せる最大流量が `Cap` に収まる

##### 計算量

- `dinic`・`flow`：$O(n^2m+n+m)$。全辺の容量が $0$ または $1$ なら $O((n+m)\sqrt m)$。二部マッチングの標準的なネットワークでは $O((n+m)\sqrt n)$。今回の最大追加流量を $F$ とすると $O((F+1)(n+m))$ とも評価できる
- `dinic`・`flow`：最大辺容量が $U\geq1$ の場合は $O(U(n+m)\sqrt m)$。平行辺がなければ $O(U(n+m)\min(\sqrt m,n^{2/3}))$ とも評価できる
- `push_relabel`：$O(nm+n^2\sqrt m)$。$m=O(n^2)$ の場合は $O(n^2\sqrt m)$

一般の上界は、探索用の辺数を使って `dinic`・`flow` が $O(n^2q+n+m)$、`push_relabel` が $O(nq+n^2\sqrt q+m)$ とも評価できる。構築と元の辺への流量配分を含む。容量に依存する上界では、元の辺の容量と、集約後の辺の容量を区別する。

自動選択では、状態の保存・再開の費用を含む各試行を幾何級数的に増やす。合計処理量は最後の試行予算の定数倍となり、Dinic が完走できる予算までに終了するため、上記の Dinic の上界を保つ。

#### get_edge / edges

```cpp
struct edge {
  int from, to;
  Cap cap, flow;
};

edge get_edge(int i) const;
vc<edge> edges() const;
```

辺の端点・容量・現在の流量を返す。`edges` は追加順に全辺を返す。

##### 制約

- `get_edge`：$0\leq i<m$

##### 計算量

- `get_edge`：$O(1)$
- `edges`：$O(m)$

#### change_edge

```cpp
void change_edge(int i, Cap new_cap, Cap new_flow);
```

辺 $i$ の容量・流量を変更する。変更後は、その辺の順方向の残余容量を `new_cap - new_flow`、逆方向を `new_flow` とする。

集約した辺の構成要素の変更、除外した容量 $0$ の辺の有効化、単独の辺の容量 $0$ への変更は、次の `build()` で反映する。単独の辺のそれ以外の変更は、探索用の容量を直接更新する。自己ループの変更は元の辺の記録へ反映する。

同じ始点・終点の最大流として継続する場合、辺全体でフロー保存則が成立するように変更する。容量だけを増やす場合は、現在の流量をそのまま指定すればよい。

##### 制約

- $0\leq i<m$
- $0\leq \mathrm{new\\_flow}\leq \mathrm{new\\_cap}$

##### 計算量

- $O(1)$

#### min_cut

```cpp
vc<bool> min_cut(int s) const;
```

現在の残余グラフで `s` から到達できる頂点を `true` とする配列を返す。`s` から `t` へ最大流まで流した後は、`true` の頂点集合が最小カットの始点側になる。

流量上限で打ち切った場合も、現在の残余グラフでの到達可能性を返す。

##### 制約

- $0\leq s<n$

##### 計算量

- 構築済みなら $O(n+q)$。再構築が必要なら $O(n+m)$
