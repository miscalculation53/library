## 概要

等差数列積の実装方針を比較し、「近い計算済みの区切りから左右を補正し、短い列は直接掛ける」方法を採用した。追加の表を持たず、長い列とサンプル5由来のクエリでは従来の約半分の時間になった。

Wilson の定理だけで階乗の逆元を省く方法の差は小さかった。今回の改善は、端数として掛ける因子数を減らす効果が大きい。

## 使用例

ライブラリ側の呼び出し方は同じ。

```cpp
Factorial<modint998244353> fac;
auto ans = fac.arithmetic_product(n, a, b);
```

比較の再実行はリポジトリのルートで行う。

```sh
g++-15 -std=c++17 -O2 -DNDEBUG -I . benchmarks/arithmetic_product.cpp -o /tmp/arithmetic_product_bench
/tmp/arithmetic_product_bench > benchmarks/arithmetic_product.csv
```

## 詳細なドキュメント

#### 条件

- 計測日: 2026-09-24。
- macOS の arm64 ホスト上で x86_64 実行ファイルを実行。GCC 15.2.0、`-O2 -DNDEBUG`。
- クエリ時間は実行順を入れ替えた 5 回の中央値。前計算と入力生成を除く。
- 前計算は同じ実行中の 1 回の時間を記録。各方式で共通の階乗表を使う。
- 乱数 seed は `20260924`。計測前に全方式の結果をクエリごとに従来法と照合する。
- 通常の乱数ケースは `a != 0` とし、0 を含まない区間を生成する。0 を含むケースは別に測る。
- サンプル由来のケースは `split_linear_mod` の分割結果と全周期の等差数列を使用する。法 1000000007 の表では同じ等差数列をその法で評価する。

#### 比較した方法

| 方法 | 内容 |
| --- | --- |
| 従来の階乗比 | `a^n * factorial(c+n-1) / factorial(c-1)` |
| Wilson | 分母の階乗の逆元を符号付きの `factorial(p-c)` に置換 |
| 内側から拡張 | 区間の内側の計算済み部分から左右へ掛け足す。長さ 32 以下は直接計算 |
| 逆階乗表を追加 | ブロック境界の逆階乗を前計算し、内側から掛け足す |
| 近い区切りから補正 | 最も近い区切りを選び、不足分を掛け、余分な因子をまとめて割る。補正より直接計算が軽いときは切り替える |

CSV には、直接計算の閾値を B・2B にしたもの、および直接計算への切り替え前の近傍補正法も含む。逆階乗表方式は短い列の判定に正規化を行うため、長さ 1〜32 の差にはその費用も含まれる。

採用版は、必要な逆階乗を Wilson の定理と既存の表から得る。補正が除算を要する場合は、その分母をまとめて 1 回だけ逆元を求める。

#### 採用の判断

内側だけから広げる方法は単純で、短い区間に有効。長い区間では、近い区切りから補正する方法が今回の両方の法で速かった。

近い区切りなら、左右の端数は通常それぞれ B/2 以下になり、内側だけの区切りを使う場合のおおむね半分の因子数で済む。法の端に近い区間では利用できる区切りの範囲に合わせて調整する。

長さ 32 以下は正規化前に直接掛ける。それより長い列では 0 を含むかを判定したうえで、`n <= |L-l|+|R-r|` なら直接計算する。長さ B 以下を無条件に直接掛ける方式は、0 を含む入力で時間が増えた。

前計算の時間と使用する表は従来と同じで、クエリの計算量も $O(B+\log p+\log(n+1))$ を保つ。サンプル4のようにクエリ数が少ない用途では、実行時間全体は共通の前計算の影響が大きい。

絶対時間と細かな差は実行環境に依存する。[全計測値](../../../benchmarks/arithmetic_product.csv)と[比較コード](../../../benchmarks/arithmetic_product.cpp)を保存している。
