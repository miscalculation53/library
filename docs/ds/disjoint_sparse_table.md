## disjoint sparse table

静的列に対するモノイドの区間積クエリを、前計算 $O(N \log N)$ 時間・空間、クエリ $O(1)$ 時間で処理する。

- sparse table と計算量オーダーが同じ。こちらのほうが適用範囲が広い。
- 「一般の $2$ 元の積は時間がかかるが、列にもとある元と一般の元の積は高速」なときにも使える。具体的には、前計算では列にもとある元と一般の元の積を $O(N \log N)$ 回、クエリでは一般の元の積を $1$ 回。
  - 他にこの特徴を持つ手法：
    - 分割統治でオフラインクエリを処理するやつ
      - これはアイデアも似ている
    - SWAG
      - これはクエリが queue や deque のようになっている場合だけ

### コンストラクタ

```cpp
DisjointSparseTable<M>(vc<M::S> v)
```

##### 制約

- `M` はモノイド

##### 計算量

`vec` の長さを $n$ として

- $O(n \log n)$

### メンバ関数

#### get

```cpp
M::S get(int p)
```

$v_p$ の値を返す。

##### 制約

- $0 \leq p \lt n$

##### 計算量

- $O(1)$


#### prod

```cpp
(1) M::S prod(int l, int r)
(2) pair<M::S, M::S> prod_left_right(int l, int r)
```

- (1)：$v_l \bullet \cdots \bullet v_{r-1}$ の値を返す。
- (2)：$v_l \bullet \cdots \bullet v_{r-1} = w_l \bullet w_r$ となるような $(w_l, w_r)$ を返す。
  - 使用場面：最終的な答えとしては一般の元の積がいらない場合（例： https://yukicoder.me/problems/no/2215 ）。

##### 制約

- $0 \leq l \leq r \leq n$

##### 計算量

- $O(1)$

### 仕組み

```
 000 001 010 011 100 101 110 111
| 0   1   2   3 | 4   5   6   7 |
| 0   1 | 2   3 ; 4   5 | 6   7 |
| 0 | 1 ; 2 | 3 ; 4 | 5 ; 6 | 7 |
```

このように仕切りを入れると、どんな（長さ $2$ 以上の）区間クエリもどこかの仕切りを跨ぐ。各ブロックについて、仕切りの場所を $M$ として $[i, M)$ または $[M, i)$ の形の累積積を適切に計算しておくことで、$[l, r)$ クエリを $[l, M)$ と $[M, r-1]$ に分けて処理できるようになる。

どの段を参照すればよいかの計算は、$l$ と $r-1$ で異なるビットのうち最上位のものを見ればよく、`msb_pos(l ^ (r - 1))` で計算できる。
