# 掃き出し・変換の剰余を遅らせる実験（2026-09-10）

測定方法・結果は [benchmark/delayed_reduction.md](../benchmark/delayed_reduction.md)、再実行用のコードは [benchmark/delayed_reduction.cpp](../benchmark/delayed_reduction.cpp)。ライブラリの利用メモとは分けて記録する。

## 採用した変更

- `Matrix` / `MatrixArray` の通常の 32 bit modint の掃き出し。行数・列数がともに 32 以上で、64 bit の作業配列に行更新を蓄積する。既に消去した列の更新と、係数が零の行更新も省く。
- 同じ modint の Hadamard 変換。長さが 1024 以上なら符号付き 64 bit 整数で変換し、最後に各要素を剰余に戻す。
- 部分集合・上位集合・約数・倍数の Möbius 変換。標準の加法群に限り、`add(a, negate(b))` を直接の `a - b` にする。Hadamard の短い配列にもこの減算を使う。

標準の 32 bit modint の型判定は `math/modint/internal_mod32.hpp` にまとめた。掃き出しは標準の体、変換は標準の加法群まで一致する場合だけ特殊化する。要素型が modint でも独自の群演算・体演算は置き換えない。内積の既存の判定も、この共通の要素型判定を参照する。

## 掃き出しの値の上限

法を $p$、正規化済みのピボット行の要素を $u$、消したい係数を $c$ とする。`x -= c*u` の代わりに、符号なし整数で `x += (p-c)*u` を蓄積する。係数が零なら更新しない。

- $p \le 2^{30}$ なら 16 回。
- $2^{30} < p < 2^{31}$ なら 4 回。

それぞれ $p + B(p-1)^2 < 2^{64}$ が成り立つ。行ごとに蓄積回数を管理し、上限に達したら残りの列を剰余に戻してから更新する。ピボット・消去係数を読むとき、ピボット行を正規化するとき、最後に値を返すときも剰余に戻す。

ピボットより下の各行について、零と判明した先頭部分を記録する。候補の探索中に残りがすべて零と分かった行は以後飛ばす。rank が小さい場合に、64 bit 配列を列方向に何度も走査する遅さを避ける。ピボットは従来と同じ「その列で最初の非零行」を選び、REF / RREF の値・rank・行列式の返り値も維持する。

掃き出しには入力コピーと別に約 $8nm$ byte と $O(n)$ の作業領域が必要。

## 変換で試した方法と不採用の理由

Hadamard・集合 zeta/Möbius・約数/倍数 zeta/Möbius について、64 bit 作業配列に移し、全演算後に剰余を取る方法を比較した。中間値は、入力の高々 $N$ 項の係数 $0,\pm1$ の和である。既存 API の長さの範囲 $N\le\mathrm{INT\_MAX}$ と $p<2^{31}$ では絶対値が $2^{62}$ 未満なので、符号付き 64 bit に収まる。

- Hadamard は一つの butterfly で和と差を作るため、補正をまとめる効果があり、採用した。直接の減算だけを使う比較実装に対しても改善した。
- 集合 zeta は元から加算後の条件付き補正しかない。64 bit 化による改善は小さく、配列の変換とメモリ増加もあるため従来のままにした。
- 集合 Möbius は従来の「符号反転＋加算」に対しては 64 bit 化も速いが、直接の減算との差は小さかった。追加配列なしで改善できる直接の減算を採用した。
- 約数・倍数の変換は 64 bit 化の変換費用とメモリアクセス増加を回収しにくかった。zeta は従来のまま、Möbius は直接の減算を採用した。

不採用の候補も `benchmark/delayed_reduction_candidates.hpp` に残してある。通常の modint オブジェクトは常に正規化済みで、剰余を遅らせる値は内部の整数配列だけに置く。

## 検証

`verify/mytest/ai/delayed_reduction.test.cpp` で、単純な掃き出しとの全要素比較、変換の定義から計算した値との比較、逆変換、境界値を確認する。対象は空・小さい配列、切替境界、長方形・零・置換・重複行・特異行列、標準の静的/動的 modint、小さい素数、31 bit 上限付近、合成数法の加法群、独自の群演算・体演算。MatrixArray の逆行列と特異/非特異連立方程式も確認する。

既存の Library Checker キャッシュでも行列式・rank・逆行列・連立方程式・XOR/AND/OR/GCD/LCM 畳み込みを確認する。連立方程式は解空間の次元に加え、返却された解・核の基底が方程式を満たすことと基底の一次独立性を検査する。オンライン提出はしていない。
