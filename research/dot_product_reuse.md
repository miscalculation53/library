# dot_product の利用箇所の調査

Codex による調査・実装メモ（2026-09-10）。計測値は [benchmark/dot_product_reuse.md](../benchmark/dot_product_reuse.md)。
利用方法と制約は各ライブラリのドキュメントに記載する。

## 今回適用した箇所

| 箇所 | 内積として扱う部分 | 切り替え |
| --- | --- | --- |
| `Matrix` / `MatrixArray` の行列・ベクトル積 | 行と入力ベクトルの積和 | 全ての代数構造で共通 API を呼ぶ |
| 同クラスの行列積 | 左辺の行と右辺の列 | 標準 32 bit modint、各辺 16 以上、左辺の非零率が 50% 以上なら右辺を転置 |
| `convolution_point_get` | $c_p=\sum_i a_i b_{p-i}$ | 標準 32 bit modint のとき、片方を逆順に読む |
| `convolution_naive` | 出力係数ごとの積和 | 両方の長さが 16 以上、両方の非零率が 50% 以上なら内積にする |
| `PolynomialRingArray` / `PolynomialRingVector` | 打切り積・全体の積の各係数 | 標準 32 bit modint、長さ 16 以上で適用 |
| `subset_convolution` | ランク付き zeta 変換後の多項式の積 | 標準 32 bit modint のとき適用 |
| `kronecker_power_array_destructive` | 各段の $k\times k$ 行列・ベクトル積 | 標準 32 bit modint、$k\ge8$ で適用 |

内積にまとめると、同じ出力要素に加算する積を 64 bit 整数に蓄積し、剰余をまとめられる。
`SR::S` が modint というだけでは分岐せず、標準の加算・乗算であることも確認する。
独自演算や他の表現の modint には従来の代数演算を使う。

`FPS::operator*` は共通の `convolution` を使うので、小さい入力などで `convolution_naive` を選ぶ部分にも適用される。
FPS の高水準の各操作全体については、今回、速度比を計測していない。

## 単純に置き換えない方がよかった箇所

- 疎な行列積や畳み込みは、全ての積を計算する内積よりも、非零項だけを展開する方が速い。
  試作段階では非零率 1% の畳み込みが大幅に遅くなったため、非零数で切り替える。
- $2\times2$ の Kronecker 作用はコンパイラが短い式に展開できる。
  内積 API の試作では約 2 倍遅くなったため、$k<8$ は従来のループを維持する。
- 行列積の密度判定には走査の追加コストがある。
  非零率 1% のケースでは、今回の実測でも約 11% の遅延が残った。全入力で高速化する変更ではない。

## さらに検討できる箇所

| 箇所 | 可能な改善 | そのまま置き換えるために必要なこと |
| --- | --- | --- |
| `Matrix::det_sparse` の CSR 作用 | 1 行の非零成分と `x[column]` の積和の剰余をまとめる | `(column, value)` の列をそのまま要素 iterator として渡せない。値・添字を読み分ける iterator、または添字付き内積を用意する |
| `DirichletConvolution` / `DirichletPrefixSum` | 約数列などに沿った積和をまとめる | 添字が不規則で、和の前後の依存関係もある。対象ループごとの測定が必要 |
| BBLA の不変因子内部の多項式積 | 係数ごとの内積を共用する | 一般ケースでは基底の消去が支配的で、この小さい積だけの高速化は優先度が低い |
| 行基本変形 | 複数列・複数 pivot の更新をまとめる | 現在は各出力への加算が 1 積ずつ。内積への置換にはブロック消去等の構成変更が必要 |
| NTT の butterfly | 表現・遅延剰余の範囲を調整する | 既に生の整数で計算している部分があり、長い内積への置換とは別の最適化 |

出力要素が毎回異なる `y[j] += c*x[j]` のような更新は、そのままでは長い内積にならない。
「同じ出力に多数の積を足すか」と「零を飛ばす利益が大きいか」が、今回の切り分けの基準になる。
